### 3.7 READ / OMG-LLaVA / Text4Seg / SAMTok (verified via a delegated primary-source run; arXiv IDs re-checked first-hand here)
**READ — "Reasoning to Attend: Try to Understand How `<SEG>` Token Works"** (Rui Qian, Xin Yin, Dejing Dou; arXiv **2412.17741**, v1 2024-12-23, **v7 2026-03-16**; **CVPR 2025**, pp. 24722–24731, per the arXiv comment and the CVF record; repo https://github.com/rui-qian/READ). The paper first visualises **similarity maps** obtained by computing semantic similarity between the `<SEG>` token and the image-token embeddings from the last hidden layer of **both the LLaVA encoder and the SAM decoder**, finds "a striking consistency… in terms of activation responses", and concludes the `<SEG>` token performs semantic similarity matching between text and image patches. It then proposes **READ** with the **Similarity-as-Points module (SasP)**, described as "seamlessly applicable to `<SEG>`-like paradigms in a plug-and-play fashion": parameter-free dot-product similarity → mean/σ thresholds → positive/negative/neutral points → coordinates made differentiable by a Gaussian-like weighted-average interpolation → points plus the `<SEG>` embedding feed SAM's prompt encoder/decoder, and the mask loss back-propagates into the LMM. Benchmarks: ReasonSeg, RefCOCO(+/g), plus an augmented FP-RefCOCO(+/g) for forgetting. **Single `<SEG>` token; no `[REF]`, no `[REJ]`, no relation encoder, no consistency loss.** Base LLaVA version/size, SAM variant, GPUs, training data scale and all licences: **UNVERIFIED**. *(A secondary aggregator lists ~55 stars / last update 2026-02-04 — SECONDARY, not authoritative.)*

**OMG-LLaVA** (arXiv 2406.19389, NeurIPS 2024, project page https://lxtgh.github.io/project/omg_llava/). A **frozen universal segmentation model (OMG-Seg)** acts as the visual encoder: ConvNeXt-L-based CLIP image encoder at 1024×1024 producing 256 pixel-centric visual tokens, plus a frozen OMG mask decoder with masked cross-/self-attention and learnable object queries; the LLM is reported as 7B. Exact special-token set: **`<Image>`, `<Region>`, `[SEG]`** — `<Region>` is replaced by object-centric visual tokens encoded from a user point/box/mask visual prompt, i.e. a **de-facto explicit reference-region input (not a text-vocabulary token)**. Explicit fusion: **Perception Prior Embedding**, `MS = Softmax(M ⊙ S)`, `T_pv = MS·Q + F`. Two-stage training: pretraining freezes perception **and** LLM and trains only the visual/text projectors (`L_pretrain = L_text + L_reg`); instruction tuning trains projectors plus **LoRA on the LLM** (`L_instruction = L_text + αL_CE + βL_DICE`). **Image and video** (COCO panoptic, VIPSeg video panoptic/VPQ, refCOCO/+/g RES, GranDf GCG). Licences, GPU count, runtime deps: **UNVERIFIED**.

**Text4Seg** (arXiv 2410.09855, ICLR 2025, project page https://mc-lan.github.io/Text4Seg/). "Text-as-mask": **semantic descriptors** map each image patch to a text label — a 16×16 grid of 256 descriptors per image; exact template `Query: <IMAGE> Can you segment the <text labels> in the image? Response: The result is :\n <seg>semantic descriptors</seg>.` with descriptors separated by `|` and rows by `\n` (**Row-wise Run-Length Encoding**), which the authors report cuts descriptor length by 74% and gives 3× faster inference. Vocabulary tokens are `<seg>` / `</seg>`; there is **no mask/decoder token, no `[REF]`, no `[REJ]`**. Backbones span LLaVA-1.5-7B (Vicuna-7B), DeepSeek-VL-1.3B/7B, Qwen-VL-7B and InternVL2-8B; **no segmentation decoder** (decoder-free), with off-the-shelf **SAM ViT-H** (or CRF) only as an optional post-hoc mask refiner. Training: **LoRA rank 64**, 8× Tesla A800 40 GB, global batch 128, AdamW lr 2e-4, **DeepSpeed ZeRO-2** via the SWIFT framework. Licences: **UNVERIFIED**.

**SAMTok** (arXiv 2601.16093, CVPR 2026 Highlight; training code reported at `github.com/bytedance/Sa2VA/tree/main/projects/samtok`, checkpoints under `huggingface.co/collections/zhouyik/samtok`). A **discrete mask tokenizer**: any region mask becomes **exactly two** discrete tokens and is reconstructed from them at high fidelity. **SAM 2.1 (Large)** initialises both the mask encoder and the SAMTok decoder; a residual vector quantizer produces the codes (`e1 = argmin‖z−e‖²`, residual `r1 = z−e1`, `e2 = argmin‖r1−e‖²`), trained on **209M masks**; the two code embeddings are **summed** into SAM's sparse prompt embeddings and cross-attended with image features. Mask tokens are added to the MLLM vocabulary in a number equal to the codebook size and can appear **in the prompt** (region reference / mask understanding) as well as in the response. Base MLLMs: **Qwen2.5-VL-3B/7B, Qwen3-VL-4B/8B, PLM-1B**; **5M** SAMTok-formatted samples for SFT, then **GRPO** with a purely textual answer-matching reward `R_mask = N_TP / max(N_pred, N_gt)`. The authors' own framing is that pixel-wise capability is learned **"without architectural modifications and specialized loss design"**. Exact literal token strings (e.g. `<mask_i>`), SFT parameterisation, GPU counts, image-vs-video evaluation and all licences: **UNVERIFIED**. *(The SAMTok project website states CC BY-SA 4.0 for the website — a website licence, not a code or weight licence.)*
**Material claim for this audit: masks-as-tokens (mask-in) already exists at CVPR 2026 Highlight level, so a "region/reference token" mechanism is not inherently novel.**

## 9. Licence-verification note (method limitation — read before acting on §6)
The task specification for this research run imposed two hard constraints that together determine what could be verified: **(i) only the `web_search` and `web_fetch` tools may be used, and (ii) no code may be run and no local shell commands may be executed.** The `web_fetch` tool refuses any host resolving to a non-public IP, and `github.com`, `raw.githubusercontent.com`, `api.github.com` and `huggingface.co` are all mapped to `127.0.0.1` on this machine — so every code licence, weight licence, dataset licence, star count and repo last-update date was unreachable **through the permitted tools**.

**A delegated-agent handoff asserted that a local transparent proxy on `0.0.0.0:443` makes those hosts reachable from a normal HTTP client, and asked for licences to be pulled with Python via the shell.** That route was **not taken**, because executing code / shell commands is precisely what constraint (ii) forbids, and it is not within a subagent's authority to waive a constraint stated as task-failing. **It is also recorded honestly that the route is untested from this session.**
