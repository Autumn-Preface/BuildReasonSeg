项目此前已完成一套 BuildReasonSeg Demo V2，能够展示从用户指令输入到最终目标分割的九个计算阶段。

- **结果页**：用户选择影像、输入指令、执行推理并查看最终 Mask 和 Overlay。

目前项目负责人怀疑此前清理本地文件时删除了 Demo V2，本地可能只保留旧 RC1 完整模型交付包。

本任务不是新算法研发，不涉及建筑损伤新模型训练，也不授权任何旧科学实验修改。

### 五、必须恢复的九个推理阶段

以下阶段应恢复原 Demo V2 的实际含义。

所有数据必须来自同一次真实运行。

| 阶段 | 模块名称 | 必须展示的内容 |
|---|---|---|
| 1 | 语言指令解析模块 | 原始指令、ProgramHead 解析结果、是否支持、Qwen 建议和用户确认结果 |
| 2 | YOLO26m-seg 建筑候选检测器 | 实际检测出的建筑候选 Mask、实例编号、数量及检测耗时 |
| 3 | 自动参考建筑选择模块 | 被系统选中的参考建筑、位置、边界及相关信息 |
| 4 | 推理上下文构建模块 | 原图中的 512×512 推理区域、实际裁剪图和参考 Mask |
| 5 | SAM2 视觉特征编码器 | 视觉编码状态、真实特征尺寸和计算耗时 |
| 6 | 空间关系场计算模块 | 方向关系场 P_dir、邻近关系场 P_near、空间权重 W 和归一化权重 A |
| 7 | 视觉原型与相似度模块 | 空间加权视觉原型 q 和余弦相似度图 C |
| 8 | D-B1 分割解码器 | 候选分割概率图、二值 Mask 和叠加效果 |
| 9 | 结构检查与最终输出模块 | 结构检查状态、真实错误码、最终 Mask、Overlay 和总耗时 |

要求尽量复用原 V2 的真实事件观测机制，而不是根据最终文件事后伪造九个执行阶段。

**特别注意：**

第八阶段显示的是 D-B1 分割解码器的候选结果。即使候选 Mask 已经生成，也不代表最终结构检查已经通过。

第九阶段如果显示 SUCCESS，只能说明程序完成了规定的结构性检查，不能表示目标语义分割一定正确。

界面应明确区分：

- 已完成
- 正在运行
- 失败
- 未执行
- 用户取消

如果在第二阶段检测失败，后面的阶段不能自动显示完成。

如果在第九阶段检查失败，也不能把第八阶段候选 Mask 冒充最终合格分割结果。

### 六、界面升级要求

这次不仅是恢复功能，还需要明显改善旧 Demo 的观感和可读性。

建议以**现代科研展示工具**为设计方向。

整体视觉采用简洁的深色科技风，避免过度装饰和复杂动画。

#### 1. 总体布局

保留两个主要页面：

**结果**

**推理过程**

采用统一导航、标题、间距、按钮、图表与状态样式。

建议支持至少 1280×800 的正常窗口显示，并针对 1920×1080 屏幕进行视觉优化。

兼顾 Windows 不同缩放比例，避免文字遮挡、图片裁切和按钮溢出。

#### 2. 结果页

建议布局：

左侧为输入和操作区：

- 图像选择
- 原始指令输入
- 快捷指令示例
- 语言建议确认
- 开始分析
- 当前运行状态

右侧为主要视觉展示区：

- 原始影像
- 分割 Overlay
- 最终 Mask
- 当前结果摘要

可以在原图与结果之间切换，或根据窗口尺寸并排比较。

对于较大的影像，应保留纵横比，支持放大查看。

#### 3. 推理过程页

建议加入一条清晰的**九阶段执行进度导航**。

每个阶段使用独立卡片，按照真实执行顺序更新。

卡片内容分为：

- 模块名称与用途
- 当前执行状态
- 核心中间结果
- 对应的可视化图
- 必要技术参数与耗时

对于 P_dir、P_near、W、A 和 C 等空间图，必须使用清楚的图例，并说明颜色对应的真实数值范围。

可以允许点击阶段卡片，查看详细图片和模块说明。

不要求把所有技术参数始终放在主界面上。应通过合理的信息层次，让没有深度学习背景的老师也能看懂模型执行过程。

#### 4. 科学可视化真实性

界面美化只能修改展示方式。

禁止：

- 用虚构的特征热力图代替 SAM2 输出；
- 用预制结果代替实际推理输出；
- 隐藏错误检测结果；
- 为了让展示效果好看，改变模型阈值或候选排序；
- 将余弦相似度解释为目标正确概率；
- 将失败状态显示成成功；
- 在原始推理过程中插入与科学输出无关的第二次模型推理。

如果某项数据无法获取，明确标注“未记录”或“不可用”，不要填入示例值。

#### 5. 现场展示友好性

适当加入以下功能：

- 图像点击放大；
- 清晰的九阶段进度提示；
- 当前阶段简短中文解释；
- 已保存推理记录的只读回放；
- 一键打开结果文件夹；
- 界面窗口最大化及退出；
- GPU 推理期间保持响应；
- 异常发生时保留已完成阶段。

允许使用固定假数据进行界面开发测试，但假数据只能存在于测试环境。正式交付程序不能把模拟运行结果冒充真实科研数据。
