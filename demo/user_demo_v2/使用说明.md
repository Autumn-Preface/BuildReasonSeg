# BuildReasonSeg 建筑空间推理分割 Demo V2

## 启动与环境

双击 **启动BuildReasonSeg Demo.bat**。程序先检查现有环境与本地模型，再打开主窗口。首次分析需要等待模型加载。离线运行，不安装依赖。

本包用于已配置电脑，Python 环境没有随包附带。请整体移动文件夹并保留 _engine、_ui、_runtime_cache 和 results。找不到环境时，可设置 BUILDREASONSEG_PYTHON 指向已有兼容 Python。换电脑需要准备兼容环境。

## 结果页：选择与分析

主窗口有两个平级页面：**结果 | 推理过程**，默认打开结果页。

1. 点击“选择图片”，选择 RGB 光学遥感 PNG、JPG 或 TIFF。灰度、多光谱与损坏文件不支持。
2. 输入指令，或点击四个快捷示例填入文字。示例只填文字，仍经过语言模型理解和确认。
3. 点击“开始分析”，查看程序解释的参考对象、方向和目标关系，再决定是否继续。语言模型给出建议也必须确认；拒绝后不会执行图像推理。
4. 分析完成后查看原图和 Overlay。成功时可“查看 Mask”；白色表示模型生成区域，黑色表示背景。
5. 点击“打开结果文件夹”查看本次结果、摘要与 Trace。失败不会生成虚假的最终 Mask/Overlay，也不会自动重试。

支持最大建筑左侧、右侧、上方或下方最近的建筑。Reference 自动选择，没有手动编号、阈值或模型选择功能。

## 推理过程页：实时切换

点击 **推理过程** 查看可上下滚动的两列九阶段卡片。运行中可以随时切回结果页；切页不会重新推理。完成的阶段逐项出现状态、数据或图像，无需等待分析全部结束。

两个页面共用一个工作线程、一次分析与一份结果。运行中开始分析及重新打开记录暂时禁用。较慢阶段保持“进行中”，不要重复启动。

| 阶段 | 可查看内容 |
| --- | --- |
| 1 语言理解 | 原指令、首次 program、是否受支持、缺失 nearest、真实建议、用户确认和最终 program。置信度不是语义正确率。 |
| 2 YOLO proposals | 所有 merged 候选的半透明 Mask、真实编号、raw/merged 数量和检测耗时。不隐藏错误候选。 |
| 3 Automatic Reference | 在同一候选图上用黄色边界高亮真实自动 Reference，列出编号、面积、置信度、bbox 和 automatic mode。 |
| 4 Reasoning Context | 原图的实际 512×512 context 位置、真正传入核心链的 RGB、Reference 边界、方向与 padding。 |
| 5 SAM2 Visual Features | 实际编码完成、特征形状、耗时。不显示虚构热力图，不保存大型原始特征张量。 |
| 6 Spatial Reasoning Fields | 实际 P_dir、P_near、W、A 四宫格。图例显示原始值范围、颜色范围与显示归一化方式；黄色为 Reference 边界。 |
| 7 Prototype & Similarity | q 是否形成及维度、同一 context 的 C 图。C 是视觉余弦相似度，不是目标正确概率。 |
| 8 D-B1 Segmentation | probability 热力图、二值候选 Mask、context 候选区域。尚未通过最终结构检查。 |
| 9 Final Guard & Result | SUCCESS/错误码、guard 状态、最终输出有效性及耗时。仅通过结构检查后显示最终 Overlay/Mask。 |

图片可点击放大，仅供查看。缩放、上色、alpha 叠加和显示归一化不会回写模型数组。颜色不是未经定义的概率；记录保留数组形状、原始范围与摘要。

## 候选与最终结果

第 8 阶段明确标注：**“D-B1 已生成候选 Mask，但尚未通过最终结构检查。”** 这是中间状态，不能当作已接受目标。若最终 E404，第 8 阶段图仍可看，结果页没有成功的最终 Mask/Overlay。

**SUCCESS 仅表示流程完成并通过当前结构检查。** 语义正确性为 NOT_EVALUATED，未通过 GT 或目标实例身份验证。请人工检查 Reference、方向与目标。Trace 是中间状态记录，不能证明语义正确，也不代表模型效果提升。

## 失败与取消

- E401：保留语言和真实 0 proposals；后续未执行。
- E402：没有可用 Reference，已有 proposals 保留。
- Context 检查失败：保留语言、YOLO、Reference 和实际生成的 context 信息。没有真实 context RGB 时不伪造该图。
- E404：D-B1 若已完成，保留候选 Mask 与 probability；最终结构未通过。
- E502：保留崩溃前完成阶段，未完成阶段显示失败或未执行。观测/记录错误明确说明本次用户交付未完成，底层计算完成也不会静默显示整次 Demo 成功。
- 拒绝解释或建议：语言阶段显示用户取消，后续未执行，不替用户同意。

失败不会清空以前完成的卡片。正在分析时关闭窗口会提示等待，不会强行终止模型。

## 保存位置与重新查看

每次分析独立保存到 results/<run_slug>/，不覆盖旧运行：

- result_summary.json：指令、program、状态、错误码、耗时、结构与语义状态。
- mask.png / overlay.png：仅科学运行 SUCCESS 时保存；观测失败时摘要区分底层运行与用户交付状态。
- trace/stage_events.jsonl：实际阶段事件序列。
- trace/trace_manifest.json：run ID、阶段状态、预览 hash、engine run root 和观测状态。
- trace/*.png：轻量预览，失败前产生的图也保留。

推理过程页点击“打开已保存过程”，选择本 Demo results 下的 trace_manifest.json。先校验文件，再显示旧记录，不重新推理。仅打开本 Demo 的记录，避免不同运行混入。

原引擎输出在 _engine/inference/output/<run_slug>/，日志在 Demo 内部。请保留完整文件夹。主页面不显示原始 traceback、隐藏权重路径或大量开发日志。

## 适用范围与限制

V2 增加可选只读观测与两页显示。模型、阈值、automatic Reference、context、空间场、D-B1 与 guard 保持原约束，展示不增加模型调用。

大图、滑动窗口、语言解析、模型加载和 CPU/GPU 快照复制可能增加等待；预览有尺寸限制，存储随运行数增加。包不含 GT 审核、训练、自动重试或跨电脑免配置环境。

首次真实分析请验收用户确认、两页切换、逐阶段更新、最终/失败保留和结果文件夹关联是否同一 run ID。
